# Commands (Claude Code)

Claude Code slash commands live one level deeper than OpenCode: under an `osx/` subdirectory. Each opencode command is also mirrored as a Claude skill (see `resources/claude/AGENTS.md` for the dual-emit rationale).

## Layout

```
commands/
└── osx/
    └── <name>.md             # Auto-generated from resources/opencode/commands/osx-<name>.md
```

Plus, the same slash command is also mirrored as a skill:

```
skills/
└── osx-<name>/
    ├── SKILL.md              # Generated from the same opencode command source
    └── references/           # Optional: per-skill reference pool when the
                              # command body references references/*.md paths
```

The full set of command files lives at `resources/claude/commands/osx/`. The full set of mirrored Claude skills lives at `resources/claude/skills/osx-<name>/`.

## Mirror generation

The Claude mirror is generated by `mise run sync-mirrors`. **Do not edit Claude command files directly** — every generated file carries an `# AUTO-GENERATED` header. To change a command:

1. Edit `resources/opencode/commands/osx-<name>.md`.
2. Run `mise run sync-mirrors` to regenerate.
3. Commit both.

The same script emits the dual-emit skill mirror. Adding or removing an opencode command automatically updates both the `.claude/commands/osx/<name>.md` legacy form and the `.claude/skills/osx-<name>/SKILL.md` modern form on the next sync.

## Frontmatter

Claude Code commands accept the full frontmatter spec. The mirror inherits the OpenCode frontmatter (with platform-specific tokens substituted):

```yaml
---
description: <one-line purpose>
license: MIT
[compatibility: <optional>]
[allowed-tools: <optional>]
---
```

The `name:` field is what Claude Code's slash-command resolver reads. On the legacy command form the filename carries it (`phase0.md` → `/osx-phase0` because the file lives under `osx/`). On the modern skill form the mirror script rewrites the frontmatter with an explicit `name: osx-<X>` field and drops the opencode-only `agent:` directive.

## Filename vs Name

| File | Frontmatter `name` | Slash invocation |
|------|--------------------|------------------|
| `commands/osx/phase0.md` | (implicit from path) | `/osx-phase0` |
| `skills/osx-phase0/SKILL.md` | `osx-phase0` | `/osx-phase0` |
| `commands/osx/review.md` | (implicit from path) | `/osx-review` |
| `skills/osx-review/SKILL.md` | `osx-review` | `/osx-review` |

The command filename omits the `osx-` prefix; the skill directory and `name:` field both carry it.

## Conventions

- The Claude mirror is **always** generated from OpenCode; never hand-edit Claude commands or skills.
- Phase commands (`phase0` … `phase6`) are the only entry points the orchestrator uses; the dispatch table is the same.
- Either form satisfies `validate_commands` — a phase command is valid as long as one of the two locations has a current file. This makes the platform stable against future Claude Code changes that may prefer one form over the other.
