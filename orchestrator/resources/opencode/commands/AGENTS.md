# Commands (OpenCode) — Orchestrator Side

OpenCode slash commands, one file per command. Phase 4 moved this
directory under `orchestrator/resources/opencode/commands/`. The
gap-filling commands (`osx-review`, `osx-verify-tests`) live on the
**skills side** at `skills/resources/opencode/commands/`.

## Layout

Flat directory: `commands/osx-<command>.md`. No subdirectories.

## Categories

| Category | Files | Side |
|----------|-------|------|
| Phase commands | `osx-phase0.md` through `osx-phase6.md` | orchestrator |
| Workflow | `osx-changelog.md`, `osx-maintain-docs.md` | orchestrator |
| Gap-filling | `osx-review.md`, `osx-verify-tests.md` | skills |

The full list lives in `orchestrator/resources/opencode/manifest.toml`
under `[resources.commands.*]` (orchestrator-side commands) plus the
skills-side manifest entries for `osx-review` and `osx-verify-tests`.

## Frontmatter

OpenCode commands use minimal frontmatter:

```yaml
---
description: <one-line purpose> # Required
---
```

## Phase Command Contract

`osx-phase0.md` … `osx-phase6.md` correspond 1:1 with the orchestrator's PHASE0–PHASE6. The orchestrator dispatches the matching command at the start of each phase. See `orchestrator/source/orchestrator/AGENTS.md` for the dispatch table.

## Conventions

- Filename `osx-<command>.md` must match the slash-command name `/osx-<command>`.
- Phase commands are the **only** entry points the orchestrator uses; do not rename or remove them without updating `PHASE_COMMANDS` in `orchestrator/source/orchestrator/engine.py`.
- Each phase command inherits the **Mandatory Start**, **Mandatory End**, and **blocker semantics** from `orchestrator/resources/opencode/skills/references/phase-protocol-common.md` and `blocker-semantics.md`. State the phase-specific differences inline; reach for the shared references for boilerplate.

## Claude Mirror

The Claude mirror at `orchestrator/resources/claude/commands/osx/` is generated by `mise run sync-mirrors`. Edit the OpenCode file first, regenerate, commit both. Token substitution handles the platform-specific bits (slash command form, ask-tool name, platform dir path).

The same script also emits a Claude **skill** mirror at `orchestrator/resources/claude/skills/osx-<X>/SKILL.md` for every opencode command. This dual-emit (legacy `.claude/commands/osx/<X>.md` + modern `.claude/skills/osx-<X>/SKILL.md`) mirrors upstream OpenSpec v1.7.0's own strategy on Claude Code. See `orchestrator/resources/claude/AGENTS.md` for the rationale.
